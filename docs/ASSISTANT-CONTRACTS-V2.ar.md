# عقود تطوير مساعد Parallax الشخصي العام للويب

الإصدار: 2.0-draft.1 — التاريخ: 2026-09-26 — الحالة: مسودة للمراجعة.

المرجع التخطيطي: [الخطة المثبتة v1.1](DEVELOPMENT-PLAN.ar.md). مرجع القبول: [مصفوفة التتبع والسيناريوهات](ASSISTANT-ACCEPTANCE-V2.ar.md). المرجع السابق: [عقد v1.0](ASSISTANT-CONTRACT.ar.md).

## 1. غرض الحزمة وحدود اعتمادها

هذه عقود سلوك وتفاعل وبيانات وقبول هندسي. «يجب» التزام مستهدف قابل للاختبار، و«يُمنع» إخلال بالعقد. لا يعني توثيق الالتزام أنه مطبق، ولا تمنح مراجعة العقود إذنًا لتنفيذ إجراءات على حسابات المستخدم. تبقى قواعد التنفيذ الحالية كما هي إلى أن تُنفذ التغييرات وتُختبر وتُوثق.

**هدف المنتج:** مساعد شخصي عام يتلقى طلبات المستخدم المتعلقة بالويب، ويفهمها ويخطط لها وينفذ ما تسمح به قدراته وتفويضه، ثم يوضح النتيجة بأدلتها. يقبل طلبًا جديدًا دون اشتراط تصنيفه ضمن قائمة حالات استخدام. إدارة الصفحات والإعدادات والاسترداد وتحسين صفحة التطبيق أمثلة قبول، وليست حدود المنتج أو تبويبات إجبارية للواجهة.

عمومية الطلبات لا تعني ضمان القدرة على كل موقع أو تجاوز حمايته. عند وجود عائق فعلي يكمل المساعد الأجزاء الممكنة، ويحدد الجزء المتعذر وما يلزم لاستكماله. النطاق الحالي محلي لمستخدم واحد، وموضوع العقود هو `parallax assistant`. يبقى فحص المواقع `parallax sweep` مستقلًا؛ الاستضافة العامة والتحكم بسطح المكتب خارج هذه الحزمة.

## 2. قواعد مشتركة

- المستخدم مصدر الهدف والتفويض والتعديلات. يستطيع إلغاء التفويض أو تعديل نطاقه.
- المحرك يقترح خطة وإجراءات وتفسيرات؛ المتحكم يقرر التنفيذ وفق الطلب والحالة والدليل.
- محتوى الموقع والملفات والنتائج السابقة بيانات تُفحص؛ لا تمنح صلاحية ولا تتجاوز تعليمات المستخدم.
- القراءة والتحضير والتنفيذ والتحقق مراحل لها آثار مختلفة. الحفظ التلقائي في موقع ما كتابة خارجية حتى لو سماه النموذج «تحضيرًا».
- يخدم السؤال قرارًا ناقصًا أو تفويضًا غير كافٍ أو تدخلًا لازمًا؛ لا يُستخدم كبديل عن عمل يمكن إتمامه.
- تُطبق العقود نفسها على المسار العام والوصفات والتكاملات وجميع المحركات. لا يتيح تبديل المسار توسيع السلطة.

## 3. عقد فهم الطلب والتخطيط العام

### G01 — قبول الطلبات المفتوحة

يجب قبول طلب طبيعي دون نوع متخصص، وبناء العمل من القدرات المتاحة والملاحظات الفعلية. الوصفة تحسين اختياري. يُمنع رفض طلب لمجرد أنه خارج أمثلة التسويق أو الحسابات، أو الادعاء بوجود أداة غير متاحة.

**القبول:** إكمال بحث أو تعامل مع نموذج على موقع اختبار لم تسجل له وصفة أو محددات خاصة. إذا احتاج خطوة غير مدعومة، ينتج الجزء الممكن وعائقًا محددًا. السيناريوهات T01 وT02 وT27.

### G02 — النتيجة والقيود والأسئلة

يجب تمثيل النتيجة المطلوبة والقيود المهمة ومقياس اكتمالها. لا تُطلب هوية حساب لمهمة لا تحتاج حسابًا. تستخدم المعلومات التي قدمها المستخدم أو أكدها سابقًا ما دامت صالحة؛ التفضيلات لا تُعد تفويضًا بإجراء مؤثر. يذكر المساعد الافتراض المنخفض المخاطر، ويسأل عن نقص يؤثر في الوجهة أو التكلفة أو المحتوى أو الموعد أو صحة النتيجة، مع متابعة العمل المستقل.

**القبول:** مقارنة معلومة القيود تبدأ مباشرة؛ طلب موعد ملتبس يُحضّر محتواه ويطلب المنطقة الزمنية قبل جدولته. لا يتكرر سؤال سبق حسمه ضمن المهمة. T03 وT04.

### G03 — خطة متكيفة وسياق متابعة

يجب تمثيل تبعيات مراحل الطلب المركب ونتائجها، وإعادة التخطيط عند ظهور معلومات أو توجيه جديد. الطلب البسيط لا يحتاج عرض خطة طويلة أو موافقة شكلية. عند المتابعة تُحفظ القيود والنتائج ذات الصلة، مع إعادة فحص الحقائق المتغيرة. تعديل الهدف لا يعيد تنفيذ خطوات مؤثرة نجحت، ولا يمنح صلاحيات جديدة ضمنًا.

**القبول:** مهمة بحث ثم مقارنة ثم تجهيز عبر موقعين تستعمل حقائق موثقة وتنفذ التابع بعد تحقق شروطه. تعديل الميزانية أثناء العمل يعيد تقييم الخطوات اللاحقة. T05 وT06.

## 4. عقد التفويض والاستقلالية

### A01 — مصدر التفويض ونطاقه

يمكن أن يكون طلب المستخدم الصريح تفويضًا كافيًا: مثل «غيّر لغة هذا الحساب إلى العربية» عند ثبوت الحساب والإعداد والأثر. يسجل المتحكم أساس القرار بصيغة مختصرة دون حفظ الطلب الخام أو الأسرار. يتضمن التفويض العملية والوجهة والحساب عند الحاجة، والبيانات أو حدودها، والتكلفة والوقت وعدد التنفيذ حين تنطبق. لا يكفي قول المحرك «مسموح» ولا اختيار تفضيل عام.

يجب تنفيذ الخطوات الداخلة في التفويض دون طلب الإذن نفسه مجددًا. لا تُحوَّل «راجع» إلى «عدّل»، ولا «جهّز» إلى «أرسل». إن لم يتضح أثر عنصر، يفحصه المساعد بوسائل لا تنفذ أثرًا، ثم يطلب تدخلًا محددًا إذا بقي الأثر مجهولًا.

**القبول:** يتنفذ تغيير لغة محدد مأذون دون اعتماد مستقل لكل تعبئة وحفظ؛ طلب مراجعة فقط لا يحفظ. T07 وT08.

### A02 — معاينة القرار الناقص

عندما لا يغطي التفويض القائم الإجراء، يجب تجهيز نسخة قابلة للمراجعة قبل طلب القرار، تشمل الهدف والبيانات والفرق عن السابق والآثار ذات الصلة. التنفيذ بلا قرار مطلوب ممنوع. يمكن تفويض مجموعة عمليات محددة مرة واحدة؛ لكل عنصر حالة مستقلة. اعتماد محتوى نهائي لا يجيز محتوى معدل خارج النطاق، والرفض أو انتهاء الصلاحية يمنع التنفيذ.

**القبول:** حزمة ثلاث مسودات تعرض نصوصها ووجهاتها ومواعيدها؛ لا يسأل المساعد عن كل نقرة داخل المعتمد. تغيير واحد خارج التفويض يعيد تقييمه دون إعادة تنفيذ الباقي. T09 وT10.

### A03 — مطابقة الوجهة والحالة وقت التنفيذ

يجب فحص هوية الموقع والحساب والكائن المستهدف قبل كل أثر، بما يكفي لتمييزه عن غيره، وتجديد رصد العنصر بعد تغير الصفحة. إذا تعذر تثبيت الهوية يتوقف الأثر المعتمد عليها. تغيير DOM الشكلي يستلزم رصدًا جديدًا، لكنه لا يلغي تفويض العملية تلقائيًا إذا بقي معناها ونطاقها ثابتين. تغير الوجهة أو الأثر خارج النطاق يبطل أهلية التنفيذ القديمة.

**القبول:** تبديل الحساب بعد المعاينة يمنع الحفظ في الحساب الجديد؛ إعادة ترتيب عناصر الصفحة مع ثبوت الهوية تسمح بإعادة التخطيط دون موافقة شكلية إضافية. T10 وT11.

## 5. عقد التنفيذ والتعافي

### E01 — إجراءات محدودة وحالة تنفيذ مستقلة

يجب الفصل بين اقتراح الإجراء ومحاولة تنفيذه وأثره. يقبل المتحكم إجراءات من نحو معلوم ومعلمات متحقق منها وأهداف مرصودة. يُمنع تنفيذ JavaScript أو أوامر shell مولدة من نص الموقع أو المحرك. أي إضافة لقدرة تنفيذ تخضع للقواعد والاختبارات نفسها، وتستخدم حدود حجم ونطاق معلنة.

**القبول:** إدخال إجراء غير معروف أو هدف مختلق يرفض قبل المتصفح. لا يُفسَّر نجاح استدعاء الأداة كنجاح الهدف. T12 وT14.

### E02 — أثر مجهول ومنع التكرار

يجب تسجيل هوية العملية ومحاولتها قبل إرسال أثر خارجي، ومنع تزامن تنفيذ العملية نفسها. إذا انقطع الرد بعد الإرسال، تنتقل إلى «أثر غير مؤكد» وتُفحص حالة الخدمة دون إعادة الإرسال. تُستخدم مفاتيح منع التكرار عندما تدعمها الخدمة. لا يُدّعى ضمان التنفيذ مرة واحدة عبر الشبكة إن لم تسمح الخدمة بذلك.

لا تجوز محاولة جديدة إلا بعد دليل موثوق على عدم وقوع الأثر أو آلية تمنع تكراره فعليًا، مع تفويض ما زال صالحًا. عدم العثور على نتيجة في قائمة متأخرة التحديث ليس وحده إثباتًا لعدم التنفيذ. لا يبرر التبديل من المتصفح إلى API تكرار أثر مجهول.

**القبول:** نجاح إرسال بعيد مع ضياع الرد أو انهيار قبل حفظ النتيجة يؤدي إلى المصالحة والتحقق، دون إعادة إرسال أو نجاح مفترض. T13 وT22.

### E03 — تعافٍ محدود وتقدم قابل للحفظ

يجب تحديد ميزانية خطوات ووقت ومحاولات قراءة آمنة، وإظهار العائق عند استنفادها. إعادة التخطيط لا تصفر الميزانية لتشكيل حلقة بلا نهاية. لا تُعامل أخطاء الكتابة معاملة أخطاء القراءة. تُحفظ نقاط تقدم غير سرية في مرحلة دعم الاستئناف؛ وتبقى النتائج الجزئية قابلة للوصول عند توقف المهمة.

**القبول:** فشل قراءة عابر يسمح بالتعافي، وتكراره ضمن الاختبار حتى الحد ينتهي بسبب واضح. لا تتحول مهلة انتظار المستخدم إلى نجاح أو موافقة. T04 وT15.

## 6. عقد التحقق والنتائج

### V01 — دليل يثبت النتيجة المطلوبة

يجب تحديد شرط نجاح مناسب قبل تنفيذ الأثر، ثم فحصه بدليل من رصد لاحق مرتبط بالعملية والوجهة والكائن والحساب عند الحاجة. لا يكفي نص عام مثل «تم» أو اقتباس صحيح لا يتعلق بالمطلوب. لكل عنصر في مهمة جماعية نتيجة تحقق مستقلة؛ لا يثبت دليل واحد نجاح الجميع.

في القراءة والتحليل يُتحقق من المصادر والحقائق المستعملة، وتُميز الاستنتاجات وحدود اكتمال البحث. لا يُعرض الاستنتاج كحقيقة مثبتة لمجرد أن مصدره مقروء. إذا تعذر إثبات نتيجة عملية عامة، تنتهي غير متحقق منها مع السبب، دون اشتراط وصفة متخصصة لتقبل المهمة أصلًا.

**القبول:** تأكيد حفظ لكائن آخر لا يثبت الطلب؛ نجاح عنصرين من ثلاثة ينتج نتيجة جزئية. T14 وT16 وT17.

### V02 — مخرج قابل للاستخدام ولا يضلل

يجب عرض المنجز والمتبقي وسبب الحالة والأدلة ذات الصلة وتوقيتها، وإتاحة النسخ والتصدير حيث ينطبق. يوضح التقرير الفرق بين مسودة ومُرسل ومقبول ومجدول ومنشور، وبين تعديل نُفذ وتحسن تجاري لم يُقَس. النتائج القديمة موسومة بتاريخها ولا تخفي فشل مهمة أحدث.

**القبول:** نجاح حفظ موعد يعرض «مجدول» دون ادعاء وقوع الحدث؛ تحليل عام بلا بيانات خاصة يصرّح بحدوده. T16 وT17 وT26 وT31.

## 7. عقد تحكم المستخدم وتجربة الاستخدام

### H01 — الإيقاف والتسلم الفعلي

يجب إتاحة إيقاف المهمة أو تسلم المتصفح أثناء التخطيط والتنفيذ. عند التسلم تُلغى أعمال التخطيط الجارية ويُوقف الرصد والخطوات اللاحقة؛ وبعد الاستئناف تُقرأ الحالة الحالية. عملية أُرسلت بالفعل قد تقع رغم الإيقاف؛ تُعرض نتيجتها كمنفذة أو مجهولة حسب الدليل، ولا يُدّعى التراجع عنها.

**القبول:** لا يصل أي رصد جديد للمحرك أثناء إدخال المستخدم رمز تحقق. إيقاف إرسال جارٍ يمنع الخطوة التالية ولا يعلن أن الإرسال ألغي دون دليل. T18 وT19.

### H02 — استئناف وسياق محفوظ دون مفاجآت

استعادة نتيجة محفوظة ليست استئناف تنفيذ. المهمة التفاعلية المنقطعة تنتظر اختيار الاستئناف، ثم تتحقق من التفويض والجلسة والوجهة والأثر السابق قبل المتابعة. يُسمح مستقبلًا بالاستئناف الآلي لمهمة مؤجلة فقط إذا استوفت S01–S03 وكانت استعادة التشغيل جزءًا من التفويض. لا تُعاد صلاحية رمز موافقة خطوة قديمة أو معرّفات DOM قديمة.

**القبول:** إعادة التشغيل لا تحفظ إعدادًا معلقًا تلقائيًا؛ تستعيد المهمة المؤجلة المؤهلة عملها بعد الفحوص دون إعادة سؤال عن تفويض صالح. T20 وT22.

### U01 — واجهة عامة وحالة مفهومة

يجب أن تسمح الواجهة بطلب حر دون اختيار نوع متخصص، وتعرض الهدف والتقدم والنتيجة في مواضع واضحة وبالعربية وRTL. يظهر الحساب أو الوجهة عندما يؤثران في المهمة. كل انتظار يشرح السبب وما المطلوب وكيف يُستأنف أو يُلغى. لا تُعرض أسماء قواعد البيانات أو رموز الحالات الداخلية بدل شرح يفيد المستخدم.

**القبول:** يمكن بدء ومتابعة طلب جديد، والوصول للإيقاف والمعاينة والنتيجة بلوحة المفاتيح، دون الدخول لقسم خاص بالتواصل الاجتماعي. T28.

## 8. عقد الخصوصية والملفات

### D01 — تقليل البيانات وحدود الجلسة

يجب الاقتصار على تبويبات وبيانات المهمة المصرح بها، وتنقية الأسرار من الملاحظات وروابط المصادر والتقارير والأخطاء. لا تُرسل كلمات مرور أو OTP أو روابط استرداد سرية إلى المحرك أو السجلات. يُوضح أن طلبات العمل ومحتوى الصفحة المسموح قد تصل لمزود النموذج. عند عدم القدرة على عزل بيانات حساسة، يُستخدم التسلم اليدوي بدل ادعاء حماية غير موجودة.

لا تُقرأ تبويبات أو ملفات غير متعلقة بالطلب. نقل بيانات بين موقعين يحتاج ارتباطًا بطلب المستخدم وتفويضًا مناسبًا؛ تعليمات الصفحة لا تجيز ذلك. T18 وT23 وT24.

### D02 — حفظ اختياري ودورة حياة واضحة

يجب فصل سجل التشغيل الأدنى عن محتوى المستخدم المحفوظ. لا يُحفظ الطلب الخام أو نص الصفحة الكامل افتراضيًا. يوضح طلب حفظ مسودة أو جدولة مهمة البيانات اللازمة للحفظ ومدته؛ يمكن أن يمنح الطلب نفسه هذا الإذن دون سؤال مكرر. تحفظ فقط مدخلات التنفيذ الضرورية والأدلة المختصرة، بصلاحيات محلية خاصة. تبقى الأسرار خارج مخزن المهام.

يجب إتاحة حذف المحتوى والمرفقات وإنهاء الاحتفاظ، مع إلغاء أهلية الأعمال المحلية التابعة أولًا حتى لا ينفذ محتوى محذوف. إزالة السجل المحلي لا تلغي أثرًا أو موعدًا لدى موقع خارجي؛ تعرض حالته ويُطلب إلغاؤه ضمن تفويض مناسب عند الحاجة. السجل الأدنى لمنع تكرار العملية له مدة احتفاظ معلنة ولا يتضمن محتوى المستخدم أو أسراره. T20 وT25 وT32.

### F01 — الملفات بمصدر ووجهة محددين

يجب حصر الرفع بالملفات التي اختارها المستخدم أو أنتجتها المهمة ضمن طلبه، والتحقق من نوعها وحجمها ومحتواها المناسب للغرض ووجهتها؛ لا يختار المحرك مسارًا اعتباطيًا على الجهاز. يعتمد التفويض نسخة الملف؛ تغير محتواه يعيد التقييم. التنزيل يُحفظ في موضع واضح ومقيد بأسماء آمنة، دون تنفيذ محتواه أو الكتابة فوق ملف قائم دون تفويض. تظل تعليمات الملفات بيانات غير موثوقة.

**القبول:** رفع ملف مختار مرة واحدة إلى الوجهة المقصودة؛ منع استبداله سرًا أو الوصول لملف خارج النطاق، ورفض مسار تنزيل يخرج من المجلد المسموح. عند غياب دعم النوع يشرح العائق ويتيح تدخلًا يدويًا. T29.

## 9. عقد الزمن والجدولة

### S01 — تفويض موعد قابل للتنفيذ

يجب حفظ العملية والوجهة والمحتوى أو قواعد اشتقاقه المحددة، والتوقيت والمنطقة الزمنية، وصلاحية التفويض وسياسة التأخير والإلغاء. يُحسم الوقت الغامض أو غير الموجود بسبب تغير التوقيت قبل التنفيذ. يُحوّل الموعد للتنفيذ مع حفظ منطقة المستخدم. التكرار، إن دُعم، يحتاج ترددًا ونهاية أو حدًا وعددًا واضحًا؛ وإلا يُعلن غير مدعوم ولا يستنتج من موعد مفرد.

يمكن تنفيذ عمل مؤجل دون اعتماد جديد عند موعده إذا بقي ضمن تفويض صالح؛ المحتوى المستقبلي غير المحدد الذي لا يغطيه التفويض ينتظر المراجعة قبل الإرسال. T04 وT21.

### S02 — ملكية الجدولة وفوات الموعد

يجب بيان هل الخدمة الخارجية أم المساعد المحلي مسؤول عن التنفيذ. الجدولة الخارجية تحتاج إثبات قبول ومعرّفًا أو مرجعًا قابلًا للفحص. التشغيل المحلي يتطلب عاملًا متاحًا وجلسة صالحة؛ انطفاء الجهاز أو انتهاء الجلسة لا يُعرض كجدولة مضمونة. عند فوات الموعد تُطبق السياسة المأذونة أو تنتظر المهمة قرارًا؛ لا يُنفذ محتوى متأخرًا بصمت.

إلغاء موعد خارجي لا يكتمل بتغيير سجل محلي: يجب التحقق من إلغائه لدى المنصة أو عرض العائق. إيقاف مهمة حالية لا يلغي مواعيد خارجية تلقائيًا. T21 وT26 وT32.

### S03 — الاستعادة والتسابق

قبل التشغيل المؤجل يجب فحص التفويض والإلغاء والموعد والجلسة والوجهة والمحاولات السابقة، وأخذ حق تنفيذ محلي واحد يمنع عاملين من إرسال العملية نفسها. بعد انهيار عامل أثناء الإرسال تطبق E02 قبل التنفيذ التالي. الإلغاء قبل الإرسال يمنع الإرسال؛ إذا وقع أثناءه تعرض النتيجة حسب الدليل. إعادة التشغيل لا تلغي الإلغاء أو تعيد عملية مكتملة إلى الصف.

**القبول:** اختبار عاملين أو تشغيلين متتابعين وانهيار بعد الإرسال يثبت عدم إرسال نسخة ثانية؛ وجود تفويض منتهي أو ملغى يمنع التنفيذ. T22 وT32.

## 10. عقد قابلية التوسع والتوافق

### X01 — القدرات والمحركات والوصفات

يجب إعلان القدرات الفعلية للمخطط وتطبيق القواعد نفسها مع Codex وAntigravity وأي تكامل. عند غياب قدرة يُستعمل مسار عام كافٍ إن توفر؛ وإلا يوضح التعذر. لا يجرّب مسارًا بديلًا لإعادة أثر مجهول. إضافة وصفة أو قدرة مرئية يجب أن تُبقي اختبار الطلب غير المتخصص ناجحًا. لا يشترط تنفيذ المراحل الأولى تغيير المحرك أو إضافة اعتماد جديد.

**القبول:** اقتراح الإجراء نفسه في الحالة والتفويض نفسيهما ينتج قرار المتحكم نفسه مع المحركين. إزالة وصفة تجريبية لا تعطل مهمة عامة تدعمها الأدوات. T27 وT30.

## 11. عقد البيانات والحالات بين المكونات

هذه معانٍ مطلوبة وليست أسماء API نهائية. توضع البنى التنفيذية عند تنفيذ المرحلة مع الحفاظ على قراءة التقارير السابقة؛ لا تُعد الأسماء الآتية واجهات موجودة.

| السجل | الحد الأدنى والمعنى |
|---|---|
| المهمة | هوية، هدف مختصر غير سري، قيود، وجهات اختيارية، مراحل وتبعيات، حالة، معايير نجاح، مراجع مخرجات وتفويضات |
| التفويض | مصدره المختصر، العملية ونطاقها، الوجهة والحساب عند الحاجة، نسخة المدخلات أو حدودها، الوقت والعدد، الصلاحية والإلغاء |
| العملية والمحاولة | هوية عملية ثابتة وهوية محاولة مستقلة، نوع الأثر، الوجهة، التفويض، وقت بدء الإرسال، نتيجة الأداة، حالة الأثر ومرجع التحقق |
| الدليل | مصدر مرصود منقح، توقيت، حساب/كائن/عملية عند الحاجة، شرط النجاح المفحوص، ما يثبته وحدوده؛ دون نسخ صفحات كاملة |
| الموعد | عملية مفوضة، توقيت ومنطقة، منفذ محلي أو خارجي، سياسة فوات، مرجع خارجي إن وجد، حالة الإلغاء والاستعادة |
| الملف المحفوظ | مصدر الاختيار أو الإنتاج، نوع وحجم وبصمة، وجهة استعمال، مدة الاحتفاظ؛ دون مسار يختاره المحرك خارج النطاق |

حالة المهمة مستقلة عن حالة أثر العملية وعن تحقق النتيجة:

| البعد | الحالات والمعنى |
|---|---|
| سير المهمة | جاهزة، قيد العمل، بانتظار المستخدم، بانتظار موعد، قيد التحقق، منتهية، متوقفة، فاشلة/بلغت الحد |
| أثر العملية | لم يبدأ، قيد الإرسال، غير مؤكد، وقع، ثبت عدم وقوعه؛ القبول الخارجي لا يعني اكتمال كل الأثر |
| اكتمال النتيجة | متحقق منها، جزئية، غير متحقق منها، مع المنجز والمتبقي والسبب |
| الموعد | مخطط، مقبول محليًا أو خارجيًا، مستحق، فائت، ملغى، منفذ/بانتظار التحقق |

الانتقالات تخضع لثوابت: لا إرسال بلا تفويض صالح؛ لا «متحقق» بلا استيفاء شروط النجاح؛ لا إعادة إرسال من «غير مؤكد» دون مصالحة؛ لا عودة من الإلغاء للتنفيذ دون طلب جديد؛ ولا قراءة للمتصفح أثناء التسلم اليدوي. إذا أكملت المهمة أجزاء فقط تبقى كل آثارها منفصلة في التقرير. لا تُستبدل قيم API الحالية لمجرد مطابقتها لغويًا لهذا الجدول.

## 12. العلاقة بعقد v1.0 وحالة التنفيذ

| مرجع v1 | عقود v2 | التغيير المستهدف |
|---|---|---|
| C01 | G01–G03 | تثبيت عمومية الطلب والخطة المتكيفة والمتابعة |
| C02–C05 | A01–A03 وU01 | تفويض العملية من الطلب عند كفايته، معاينة عند نقص القرار، وعدم إعادة الموافقة بلا تغير نطاق |
| C06 | E01–E03 وV01 | تسجيل المحاولات والمصالحة وأدلة مرتبطة بكل أثر؛ منع التكرار بدل وعد مطلق بتنفيذ مرة واحدة |
| C07 | V02 وU01 | مخرجات عامة قابلة للاستخدام مع الفصل بين النتيجة والأثر التجاري |
| C08 | H01–H02 وS01–S03 | إبقاء التحكم اليدوي؛ استثناء مستهدف لاستعادة مهمة مؤجلة مفوضة، بشروط جديدة صريحة |
| C09 | D01–D02 وF01 | حفظ مدخلات مختارة للمهام المستمرة، دورة حياة وملفات وتنقية الأسرار |
| C10 | X01 | القواعد نفسها للوصفات والتكاملات والمحركات |

وفق قراءة الكود في 2026-09-26: توجد إجراءات JSON محدودة ومعاينة مرتبطة بالصفحة، وتسلم وإيقاف، وحالات `verified/partial/unverified` مع فحص اقتباس من رصد متصفح. بذلك فإن وصف فجوة الاكتمال في القسم 5 من v1 قديم؛ لكن التحقق النصي الحالي لا يثبت استيفاء V01 لكل كائن وأثر، ولا يحقق التفويض العام أو الحفظ القابل للاستئناف أو الجدولة. توجد اختبارات لبعض هذه الأسس، ولم تُشغّل ضمن إعداد هذه الحزمة التوثيقية.

عند تنفيذ كل مرحلة يُسجل لكل التزام: غير منفذ، منفذ جزئيًا، أو متحقق باختبار محدد ونسخة كود وتاريخ. تظل v2 مسودة مراجعة حتى توثيق قرار اعتمادها؛ اعتماد المتطلبات لا يساوي اكتمال التنفيذ. لا تُعد هذه العبارة طلب موافقة إضافية على إعداد الوثائق أو الأعمال التي سبق أن أذن بها المستخدم.

## 13. بوابة مراجعة الحزمة

تُراجع عمومية المنتج واستقلال الوصفات، وكفاية التفويض وتقليل الأسئلة، وشروط إثبات النجاح، وسياسة حفظ البيانات، واستثناء الاستئناف المؤجل. يُسجل أي تعديل مع معرّفات العقود والسيناريوهات المتأثرة قبل تنفيذ السلوك الجديد. المرجع الاختباري الملزم للإصدار هو مصفوفة القبول، ويكون الفشل في حدود التفويض أو منع التكرار أو منع تسريب الأسرار مانعًا لإصدار القدرة المتأثرة.
